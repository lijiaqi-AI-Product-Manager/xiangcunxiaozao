## 三、这一批自己找出的问题（13 条）

**测试和看图时发现、已修好的（5 条）**

1. **全部菜都退了的单还在后厨队列里**：看截图 07 时发现，订单还显示「待制作，预计约 16 分钟」，后厨会白做一桌已经退了钱的菜。已改为：还没做完的单如果所有菜都退了，自动转「已取消」（原因：全部菜品已退款）；已经做完的单保持「已完成 + 已全额退款」。两种情况都有测试。
2. **金额被拆到两行**：窄屏上「RM」和「40」分在两行。已在货币符号后用不换行空格。
3. **书法菜名断行难看**：占位图里出现「招牌跳跳 / 蛙」。已改为自动平衡行宽，并略缩小字号。
4. **写完代码、运行之前发现的两处问题**：
   - 同一行菜在一次退款请求里写两遍，能绕过「最多还能退几份」的检查；
   - 防重复提交的查找条件把下划线当成了通配符。

   两处都已改。防重复检查也挪到了最前面，手抖点两下时直接返回已退的结果，不报错。
5. **一个旧测试写死了「数据库升级脚本有 4 个」**：新增第 5 个后它就失败了。已改为按文件实际数量核对。

**需要老板定的（4 条）**

6. **合付单部分退款时，钱先退哪一边**：目前先退回储值，储值退完的部分再进「待柜台退还」。好处是顾客立刻拿回钱，柜台少碰现金。如果要「先退现金」或「按比例退」，需要你定。
7. **纯现金单被取消，也会进「待柜台退还」**：因为系统不知道顾客当时付没付钱，所以每一张都要店员点一下「已退还」或「未收款，无需退」。这样账最清楚，但店员要多点一下。如果只想让「合付单」进这个列表，请告诉我。
8. **全部菜都退了就自动取消（第 1 条）**：这是我加的规则，28号没写，请确认。
9. **「今日售罄」在午夜恢复**：和营业日分界点是同一个问题。如果店里营业过 0 点，凌晨的售罄设置会在 0 点被清掉。营业日分界点定下来后两处一起改。
