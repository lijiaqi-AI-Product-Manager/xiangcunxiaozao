## 一、做了什么（打个比方）

菜单页像商场的货架，详情页像拿起一件商品翻过来看说明书。顾客在菜单上点菜名或菜图，进入这道菜的「说明书」：

| 区块 | 内容来源 | 说明 |
|---|---|---|
| 合拢图 | 图片字段（现在全空） | 成品态：浅色底 + 书法菜名 + 印章小样 +「成品图上线中」（26号占位规则）；骨架态：灰块 |
| 菜名 / 编号 / 价格 / 一句话 | 批准稿 ① | 成品态菜名用书法字 |
| 拆开看看 | ③ 食材档案 | 见第二节 |
| 详细介绍 | ② | |
| 源流 | ④ | 米色纸底卡片（09号 §五.2） |
| 工序三步 | ⑤ | 三格横排 + 序号圈（P系图标到了就换） |
| 风味之路 | ⑥ | 先做文字标签；M0 地图面板等图（09号 §五.4） |
| 底部加购栏 | — | 价格 + 加减按钮（售罄显示「今日售罄」），购物车有东西时出现「去结算」 |

另外三处顺手做的体验细节：
- **返回不丢位置**：从菜单第 40 道菜点进详情再返回，回到原来的分类和滚动位置，不用从头翻（自动测试已验证）。
- **旧链接不报错**：已下架的菜，详情链接打开只显示「没有找到这道菜」+「回到菜单」。
- **从一道菜跳到另一道菜，「拆开看看」自动合拢**，不会沿用上一道的展开状态。

## 二、拆开看看：双轨怎么落地

| 等级 | 做法（24号 #15） | 图到了以后 | 现在（图全空） |
|---|---|---|---|
| S 级 27 道（D/E/V 区） | 双图法 | 展开显示 9:16 分解图 + 下面的食材清单 | 食材层 |
| B 级 41 道（A/B/C 区） | 标注层 | 在合拢图上按坐标标出每样食材 + 食材清单 | 食材层 |
| 饮品 / 主食 | 不做 | — | 没有按钮，食材档案单独成卡 |

**食材层**＝09号 §五.1 高斯定案的交互：点「拆开看看」→ 食材一层一层从下往上升起来（每层错开 120 毫秒），点「合拢」倒序收回。手机开了「减弱动态效果」的顾客直接看到展开结果，不播动画。
**批准稿没写食材的菜，不显示「拆开看看」按钮**——按钮点开是空的，比没有按钮更糟。

## 五、我自己发现的问题（7 条）

1. **「风味之路」文字里带着内部制作备注**（最需要你看）。批准稿 ⑥ 的原文是例如「湖南·长沙（R1 湘江灶台）」「陕西技法×湖南做（R9 油泼之路，跨点标注陕西→湖南）」，括号里的 R1/R9、「跨点标注」看起来是给画师的插画编号和施工说明，不是给顾客看的。按规矩我**一字没改、原样显示**（见截图 2 底部）。三个办法：A. 把括号部分从顾客端隐藏（数据不动，只是不显示；**推荐**）；B. 军师出一版顾客用的⑥文案；C. 保持原样。
2. **E01 招牌跳跳蛙不适合做基线样张**：第三批自动测试给它上传过一张「测试图片」并改价到 52（只发生在测试用的独立数据库里，开发库和真实数据不受影响）。所以基线 S 级样张换成了 E06 湘味油泼牛肉。
3. **标注层（B 级）带坐标的显示还没真正跑过**：现在没有任何合拢图、也没有任何坐标数据，代码路径写好了，但没有真实样本能验证标签位置是否压住菜。等第一张 B 级合拢图 + 坐标到位，我会补一条自动测试和一张截图。坐标的数据格式已加进数据合同（`annotations`：食材名 + 0–1 的相对位置），校验脚本会拦住「标注的食材不在食材档案里」这种错误。
4. **数据合同改了两处**（加字段，不改不删）：菜品加 `annotations`（默认空）、订单加 `autoCancelled`。旧数据全部兼容，114 项单元测试 + 8 项端到端测试全过。
5. **工序第三步文字较长时三格会挤**：如 E06「码辣子花椒、滚油一泼上桌。」在 375 宽手机上折成两行，可读但不整齐。P系图标到了以后格子会更紧，届时可能要改成竖排三步。请你看截图判断现在能不能接受。
6. **源流卡没有 R系插画**：09号 §五.2 要求「插画 + 文字左右分栏」，插画还没生成（禁止抢跑出图），现在只有文字 + 米色底。插画到了只需填图片字段，不用改页面。
7. **书法字仍从谷歌字体加载**：上轮 #13 要求自托管，排在 P3 第④项。在马来西亚/中国部分网络下，书法字可能加载不出来，届时自动退回楷体（不会空白），但成品态观感会打折。
