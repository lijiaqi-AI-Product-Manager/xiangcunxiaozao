# P3 第四批交付说明：书法字体自托管 + 图片压缩（第④项）

> 分支 `p3/dish-detail`。39号已批准三项下载；本批不改任何界面外观（大改要等消化确认单审过，见 `docs/design/redesign/01-消化确认单.md`）。

## 一、书法字体自托管

打个比方：以前顾客每次打开页面，都要去谷歌那里「借」一整本字帖（几 MB），马来西亚 / 中国网络下经常借不到；现在我们只把要用的几百个字抄下来，放在自己店里。

| 项目 | 结果 |
|---|---|
| 字体来源 | 马善政体，Google Fonts 官方开源仓库 `google/fonts`，SIL OFL 1.1 许可（允许自托管和裁剪），许可证原文随字体一起放在 `brands/<店>/fonts/source/OFL.txt` |
| 裁剪范围 | 只留顾客端用书法画的字：全部菜名、全部食材名（拆开看看）、印章字、水印字、店名，加英文数字（「100 Plus」「Tiger啤酒」这类菜名要用）。共 **318 个字** |
| 大小 | **5720.6 KB → 104.7 KB**（小了 98.2%） |
| 加载方式 | 从自己的服务器加载（`/brand-font/brush-subset.woff2`），页面一打开就预加载；字体到之前先用系统楷体显示，不会空白 |
| 谷歌字体 | 顾客端**不再发任何请求到谷歌**（端到端测试逐个请求检查） |
| 新字拦截 | 以后加新菜出现字体里没有的字，**数据校验直接报错**并提示 `npm run build:font` 重新生成，不会上线后才发现缺字 |

实测：详情页书法标题、占位图菜名、印章、水印和换字体前完全一样（截图对照 `docs/screenshots/p3-batch1/` 基线）。

## 二、图片压缩到 300KB 以内

| 位置 | 做法 | 实测 |
|---|---|---|
| **上传侧**（老板端上传菜品图） | 浏览器里先缩到最长边 1600 像素、转成 WebP，超过 300KB 自动降质量、再不行缩尺寸；老版 Safari 不会编 WebP 就退回 JPG。上传后在那一行告诉老板「图片已压缩：2.9MB → 220KB」。不装任何库 | 一张约 2.9MB 的 2400×2400 照片 → **220KB**，服务器存下的文件 ≤ 300KB，能正常显示（截图 `docs/screenshots/p3-batch4/老板-上传大图自动压缩.png`） |
| **出图侧**（生图管线批量出的图） | `npm run compress:assets`：默认只出报告；加 `--write` 才压缩，并且**原路径、原格式写回**，菜单数据里的图片路径一个字不用改（数据层零改动） | 照片类 JPG、WebP，插画类 PNG 都能压到 300KB 以内；现在 `assets/` 还没有图，脚本会说「无需压缩」 |

## 四、我自己发现的问题（7 条）

1. **开发工具链本来就有 5 个安全漏洞**（2 个严重、1 个高危）：在 vitest、vite、esbuild、tinypool 这些**只在开发电脑上跑**的工具里，不是这次装的两个工具带来的，也不会进顾客页面。修复要大版本升级（vite 5 → 新版、vitest 3 → 新版），可能牵动构建配置，建议单独一批做，不和大改混在一起。
2. **带颗粒的照片存成 PNG，保持原格式可能压不到 300KB**：实测一张平滑插画 PNG 原来会卡在 313KB，原因是调色板压缩的「抖动」在渐变上加了噪点；已改成有抖动、无抖动各试一次取小的，现在能压到。但纯噪点这类极端图仍然压不下来，脚本会如实标 ⚠，并估算转 WebP 后的大小。**建议生图管线直接出 WebP**（导入单里写 .webp 路径），从源头省掉这一步。
3. **上传侧压缩在浏览器里做，不是 100% 保证**：极老的浏览器或认不出的图会原样上传（服务器仍有 5MB 上限和格式检查，不会存坏图）。要做到 100%，得在服务器上也装 sharp 做兜底压缩；39号批准的是开发依赖，服务器端用要另外批准。
4. **字体原文件（5.7MB）放进了仓库**：以后加新字要用它重新裁剪，所以要留着；OFL 许可允许再分发，许可证也一起放了。如果不想仓库变大，可以改成放在仓库外、只留裁剪后的小字体，代价是换电脑后不能直接重新生成。请定。
5. **大改以后书法字会用到更多地方**：现在的字表只管菜名、食材名、印章、水印、店名。消化确认单里提到的分组标题、空状态文案如果用书法，要同步把它们加进字表（`scripts/brush-chars.ts`），否则缺字检查会拦住。这是好事，但要记得。
6. **单元测试变慢了**：图片压缩测试要真的编码图片，整套从约 2 秒变成约 10 秒，可以接受。
7. **上一轮比稿的生成脚本原来用谷歌字体链接**：品牌配置去掉谷歌链接后，重新生成会丢书法字。已改成用自托管字体；已交付的比稿文件保持原样，没有重新覆盖。

## 五、需要你拍板

1. 第四节 #1：开发工具链安全升级要不要单独排一批（推荐单独做）。
2. 第四节 #3：上传侧要不要加服务器端兜底压缩（要把 sharp 装成服务器依赖）。
3. 第四节 #4：字体原文件留在仓库里还是放到仓库外（推荐留在仓库）。
