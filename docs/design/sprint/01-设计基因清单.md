旧版实测还有三个 bug，说明它的「设计感」不等于「做得对」：
1. **375 宽手机上菜卡右侧被切掉**（`旧版-2-点单.png`：菜名「西瓜海底椰霸王杯（一升桶）」和一句话都被截断）。左边分类竖栏吃掉了宽度。
2. **详情页标题写死成「农家一碗香」**：点任何一道菜，页面顶部标题都是「农家一碗香」（截图里点的是西瓜饮品）。
3. **「立即下单」按钮常年是半透明的弱态**，和「加入购物车」两个主按钮并排，顾客不知道该点哪个。

## 二、六维基因清单（吸收 / 改造 / 丢弃，每格都写理由）

### 1. 色彩

| 吸收（照用） | 改造（保留意图换手法） | 丢弃（明确不要） |
|---|---|---|
| **红色当「决策色」，凡是要顾客动手的地方都用同一个红**：价格、+ 号、选中态、主按钮、步骤序号、「拆开看看」。理由：餐饮场景里红 = 食欲 + 行动号召；新版现在红只出现在价格和 + 号，「我的」页几乎没有红，这正是病灶③。 | **暖意从哪来**：旧版把整个底色、文字、线条都染成棕色（纸 #F7F2E9、墨 #3B2F23、线 #D8CDB8），烟火气是「全局染色」得来的。新版底色和文字是锚（#F7F7F5 / #333），不能动，所以暖意改由局部承担：占位图米色底、印章红、少量暖色块（招牌标记、会员卡），而不是全局染棕。 | **红色 TabBar 选中态**：旧版底部导航选中是红色。23号 §五.1 已定 TabBar 学喜茶「白底、黑选中、灰未选、无彩色」，导航不该和「下单」抢红色。 |
| **红的三种浓度**：实心（主按钮）/ 描边（次按钮）/ 10% 浅底（「问」字圆标、提示底）。理由：同一个红分三层，主次自然出来，不用加新颜色。 | **两种红合并成一种**：旧版价格用辣椒红 #C8402A、按钮用橙红 #D9531E，同屏两种红显脏。改成一个品牌红 + 三种浓度。 | **桌面「暗色木桌」背景**（深棕渐变 + 左侧竖排店名 + 右下印章）：顾客只在手机上扫码点单，桌面氛围是演示用的；而且店名直接写在样式里，违反「品牌走配置」。 |
| — 状态色沿用新版：成功绿、警示红、售罄灰（28号已定）。 | | **售罄黄色标签**（#A87A22 黄底）：28号已定售罄是整卡置灰；多一种黄色只会稀释红色的决策含义。 |

### 2. 布局

| 吸收 | 改造 | 丢弃 |
|---|---|---|
| **紧凑左图右文 + 加号在最右**：新版本来就是这个结构，问题出在尺寸。吸收旧版的密度：缩略图 64–72 像素、一句话截成一行、卡片间距 10 像素，目标一屏 ≥ 6 道。理由：点单是「找」的过程，一屏多看几道比每道看得大更重要。 | **左侧分类竖栏**：意图是分类常驻、一点就跳。旧版的手法把宽度挤没了（实测右侧被切），还用了 emoji 图标（不在品牌体系里）。比稿时**作为三个方向之一试**：竖栏收窄到 72 像素、去 emoji、分类名用黑体。另两个方向保留顶部横滑分类。 | **独立的「首页」和满屏大标语**：23号已定四个页签（点单 / 取餐 / 会员 / 我的），首页内容并进点单顶部。旧版首页首屏一道菜都看不到；标语「一碗香，见真章」不在任何批准稿里，不能用。 |
| **详情页「舞台卡」**：大视觉区占首屏，「拆开看看」做成实心红胶囊按钮压在视觉区底部正中。理由：入口和画面是一体的，一眼就知道这道菜能拆开看；新版现在是图下面单独一行「拆开看看」，存在感弱。 | **首页四个「信任徽章」**（明厨亮灶 / 当日现采 / 鲜肉现切 / 一菜一锅）：意图好，治病灶④（没有湘菜情感）。改造成点单页顶部一行小字信任条；但只能用批准稿里有的说法：「明厨亮灶」「当日现采」「一菜一锅」在 08号问答里有，**「鲜肉现切」在任何批准稿里都没有，不能用**。 | **详情页「口味定制」面板**（甜度、冰度、免葱蒜、免香菜、免味精、少油、少盐、五个辣椒）：违反 24号 #5（辣度在结算时选、写进备注）；「免味精 / 少油」等选项是旧版自己编的；又在下单前多加一道关卡（下单防御机制是禁止项）。 |
| — | **卡片主次**：旧版和新版一样，所有菜卡长得一样（病灶②）。比稿时有一个方向专门试「招牌菜大卡 + 普通菜小卡」。 | — |

### 3. 字阶

| 吸收 | 改造 | 丢弃 |
|---|---|---|
| **价格放大加粗**：旧版列表价格 17 像素、详情 23 像素，红色粗体，价格是一眼能扫到的锚点。新版列表价格和菜名一样 16 像素，扫不出来。 | **书法体的使用边界**：旧版 26 处用手写体，13 像素的分类名也用。规则改成：**书法只用在 ≥ 20 像素的「标题位 / 仪式位」**（详情页大标题、取餐号、空状态、区块标题二选一），列表菜名、价格、描述、按钮、分类名一律黑体。理由：书法字小了就认不出（33号警告 2）。 | **ZCOOL KuaiLe（站酷快乐体）**：卡通圆体，偏「可爱快餐」，和「喜茶克制 × 湘菜烟火」不搭；29号 #13 已定马善政书法体。 |
| — | **31 种字号收成字阶**：比稿时每个方向只允许 5–6 级字号（例如 12 / 14 / 16 / 20 / 28 + 价格专用），不许逐个元素微调。 | **逐个元素调半像素**（13.5、14.5、15.5…）：没有规律，换一个页面就乱。 |

### 4. 组件

| 吸收 | 改造 | 丢弃 |
|---|---|---|
| **黑底购物车摘要条 + 红色去结算**：新版已经有，保留。 | **列表缩略图的占位**：旧版是浅米色方块里一个红色书法大字（菜名首字），64 像素小图里很清楚。新版按 26号规则在 104 像素里塞「整个菜名 + 实拍图上线中 + 印章」，缩到 64 像素会挤成一团。**改「首字占位」要改 26号规则，需要拍板**（第四节问题 3）。 | **详情页双主按钮**（加入购物车 + 立即下单）：两个按钮抢注意力；「立即下单」绕过购物车直接确认，和服务器购物车、结算三步（23号 §3.3）冲突。新版保持「加减数量 + 去结算」。 |
| **加购时购物车数字弹一下**（徽标放大到 1.45 倍再回弹，0.45 秒）：成本极低的反馈，顾客确认「加进去了」。 | **会员卡做成深色卡**：旧版用棕金渐变 + 右下大「灶」字水印，是「我的」页唯一的视觉锚，正好治病灶①（像后台设置页）。手法换：颜色走 token（炭灰或品牌红），水印字取品牌配置里的印章字，不写死。 | **门店信息的「左标签右内容」虚线表**：旧版也是这样，和新版犯的是同一个病（VLM 说的表单化）。比稿时改成图标 + 一句话的信息条。 |
| **做法三步的实心红序号圈**：比新版的描边圈更有力，也是红色决策色的一部分。 | **常见问题的「问」字圆标手风琴**：红色 10% 浅底圆圈里一个书法「问」字，比新版的纯文字折叠更像 C 端产品。圆标里的字是 12–15 像素以内的单字，属于点缀，不违反书法边界。 | — |
| **拆开后的食材标签卡 + 虚线引线**：给 B 级标注层用（合拢图上标食材的位置）。新版标注层现在只有圆角小标签，引线能让「这个标签指的是哪块」更清楚。 | — | — |

### 6. 动效

| 吸收 | 改造 | 丢弃 |
|---|---|---|
| **「拆开看看」按钮轻呼吸**（2.4 秒放大到 1.03 倍再回来）：只有这一个按钮、幅度很小，作用是让顾客发现这个功能。限定：全站只此一处，不扩散。 | **页面切换淡入 + 菜卡逐个上浮**：意图是质感。改成只在第一次打开时做一次，以后切页、滚动不再重复——86 道菜每次进来都上浮一遍就廉价了。 | **锅铲无限摇摆、骨架屏无限闪光**：等待页上无限循环的动画耗电、分散注意力，违反 26号克制原则。 |
| **减弱动态效果时全局降级**（旧版把所有动画压到 0.01 秒）：新版只有拆开看看做了降级，比稿时全局都要做。 | — | **镬气油光罩、热气、酱汁飞溅等舞台特效**：全是前端用代码画的矢量效果，23号 §五.3 明令禁止矢量插画的规整感；新版菜品图走生图管线，不需要代码画。 |

## 三、给比稿的约束（从清单里收出来的）

1. 锚不动：底色 #F7F7F5、文字 #333、179 像素水印、印章。
2. 红色一种、三种浓度，覆盖所有「要顾客动手」的地方；TabBar 仍是黑白。
3. 书法只上 ≥ 20 像素的标题位 / 仪式位；列表全黑体。
4. 字号 5–6 级，间距 4 的倍数，禁止逐个微调。
5. 点单页一屏至少 6 道（三个方向都要报实测数）。
6. 文案只用批准稿里有的；没有的写「待提供」，不编。
7. 动效只在三处：加购徽标弹跳、拆开看看错峰、首次进入一次性淡入；减弱动态效果时全部关掉。

**三个方向的初步设想**（审过再展开，现在只写方向名，不出稿）：
- A「紧凑效率」：旧版精华加强版，一屏 7–8 道，顶部横滑分类，红色最浓。
- B「主次大卡」：喜茶式，招牌菜大卡 + 普通菜小卡，留白多、红色只在价格和按钮。
- C「纸本菜谱」：去卡片化，分隔线 + 留白，左侧窄分类竖栏，像翻一本菜谱。

## 四、需要军师 / 老板回答的问题

1. **喜茶小程序包在哪？** 33号说在 `food_apps/`（26 MB），这台电脑上没有。没有它，「喜茶的列表卡片结构、色彩节奏」只能用 23号的二手总结。能找到就发路径；找不到的话，我按现有资料比稿，报告里写明这一项缺。
2. **详情页大标题用不用书法？** 34号写「菜名主体保持黑体，书法只做水印 / 点缀」，但已转正的基线（26号规则）详情页大标题是书法。我建议：≥ 20 像素的详情页大标题保留书法（基线已认），列表菜名用黑体。要你们定。
3. **列表缩略图能不能改「首字占位」？** 26号规则是「浅色底 + 书法菜名 + 印章」。缩略图缩到 64 像素后整个菜名放不下，旧版的「一个红色大字」更清楚。改的话是改 26号规则。
4. **信任条能不能上点单页顶部？** 只用 08号问答里有的三句（明厨亮灶 / 当日现采 / 一菜一锅）。

## 五、我自己发现的问题
