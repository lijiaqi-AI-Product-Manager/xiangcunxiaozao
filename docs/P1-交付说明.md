## 三、自查发现的问题（9 条）

**需要军师处理的（文件之间的矛盾）**

1. **S 级名单数字对不上**：24号 #15 写「D区15 + E区13 + V区2 = 30 道」，但 D 区热菜只有 12 道；15 是把 3 个罐装饮品也算进去了，而同一条又说罐装不做拆开看看。按分区规则实际是 **27 道**。另外 #15 说的「16号规格书 §菜品分级名单」我没收到——这次随包只有 04/08/09/11/21/22/23 七份文件。
2. **问 1 纠错后语序颠倒**：按 24号 #16 原样替换后，答案是「鸡蛋炒散先出锅定形，最后回锅裹汁、肉片煸出油脂、青椒木耳单独断生，猛火合炒三十秒……」，「最后」出现在其他步骤之前。我只做了原样替换，没有改写，建议军师给一整句定稿。
3. **菜名改了，文案没跟着改**：22号裁定菜名以清单为准，但挂上去的文案还是按旧菜名写的。最明显的是 B11 显示「清炒油麦菜」，文案却写「菜单不写死菜名，因为时令说了算」。另外 C04 小炒牛肚 / C05 小炒黄牛肉的文案主打香菜，E07「干煸肥肠」的文案讲的是「干锅越烧越入味」。是否改文案，需要军师判断。

**需要老板确认的**

4. **10 个设计 token 是我暂定的**：23号只说「红椒红 / 腊味棕做点缀、椒绿成功态、剁椒红警示态」，没给色值。我暂定品牌红 #C8372D（白字对比度 5.2:1，达标），其余见 `tokens.json` 的 provisional 列表。
5. **列表里菜名出现两次**：没图时，占位块里写菜名，旁边标题也写菜名，视觉上重复。规格要求占位显示菜名，所以先照做；出图后自然消失。如果觉得碍眼，列表页的占位可以只留「实拍图上线中」。

**环境与工程层面的**

6. **异地备份还不是真的异地**：本地快照和数据库在同一块硬盘上，硬盘坏了两者一起丢。Litestream 实时复制要等「服务器 + 对象存储桶」定下来才能真正运行，目前只有模板，没有实测过。
7. **项目目前放在本次会话的临时文件夹里**：会话删除，文件夹一起删除。而且这个文件夹被 Windows 做了虚拟化，导致 npm 的工作区链接和 Vite 的真实路径都读不到（已用路径别名绕开，现在能正常运行）。git 也因为路径超长无法在这里建仓库，所以**这一批还没有版本记录**。迁到固定文件夹后第一件事就是建仓库、提交这一批。
8. **和 P0 提案的一处技术偏差**：提案写了用 Drizzle（一个数据库工具库），P1 改为直接写 SQL 迁移文件。原因是账本的禁改禁删规则用数据库触发器写最直接，也方便审查。P2 写业务查询时再评估要不要引入。
9. **截图没有存进仓库**：浏览器截图工具不落盘，这一批的截图只在对话里。P2 起加自动截图脚本（Playwright），每批截图会自动存档。
